# Правила внесения изменений

1. Каждое изменение начинается с issue с целью и критериями готовности.
2. Для issue создаётся ветка `feature/<name>`, `fix/<name>` или `docs/<name>`.
3. Коммиты небольшие и понятные: `feat:`, `fix:`, `test:`, `docs:`, `chore:`.
4. Перед push обязательно выполнить `make verify`.
5. Изменения попадают в `main` только через MR/PR после просмотра diff.
6. Конфликты разрешаются в рабочей ветке; после разрешения проверки повторяются.
7. Секреты, `.env`, локальная БД, `.venv` и кэши не коммитятся.
8. Версии отмечаются аннотированными тегами вида `v0.1.0`.
