Покрытие двух сред немного различается из-за чтения переменных окружения
при импорте приложения; оба прогона превышают неизменённый порог.

Миграционные тесты проверяют 001 → 002 → 003, чистую базу и заполненную БД
v0.1.1. Сравниваются исходные значения во всех семи таблицах, включая хеш
пароля, сессию и цену продажи. Ошибка после ALTER TABLE откатывает изменение
и сохраняет прежнюю версию. Повторный upgrade не меняет данные.

Тесты восстановления проверяют данные после UPDATE и DELETE, новый файл,
живой WAL, копию старой схемы, повреждённый источник, отсутствующий источник,
запрет неявной перезаписи и сохранение прежней цели. CLI-команды также покрыты.

Мутации: снятие ограничения цены (1 падение assertion), запрет продажи ровно
по стартовой цене (2), удаление HALF_UP (2). Ошибок импорта/подготовки нет.

Полный браузерный E2E-сценарий не автоматизирован и не засчитан как FR-11.
Интерфейс содержит новое поле комиссии; API и финансовые расчёты проверены.
Рабочая БД пользователя и его серверы в проверках не участвовали.
Описание выполненных действий приведено в [отчёте ЛР3](lr3.md).

Машиночитаемые отчёты создаются командой `make verify` в reports/:
JUnit XML, XML/HTML coverage, Bandit JSON, functional-coverage JSON и mutations JSON.
Они не коммитятся: этот документ фиксирует фактический выполненный прогон.
