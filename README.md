# Auction Service — ЛР1

Мы разработали учебную систему для учёта аукционов, лотов, участников и
результатов продаж. Приложение содержит HTTP API, реляционную базу SQLite,
аутентификацию оператора и адаптивный веб-интерфейс.

Текущая версия: `v0.1.1`.

## Реализованные возможности

- регистрация первого оператора, вход и выход из системы;
- серверные сессии с `HttpOnly` cookie;
- создание продавца и покупателя;
- создание аукциона и добавление лотов;
- переход аукциона `DRAFT → OPEN → CLOSED`;
- переход лота `DRAFT → AVAILABLE → SOLD/UNSOLD`;
- транзакционная регистрация продажи;
- запрет повторной продажи и продажи ниже стартовой цены;
- просмотр лотов выбранного аукциона;
- отчёт по количеству продаж и общей выручке;
- единый формат ошибок, health-check и readiness-check;
- интерактивная документация Swagger/OpenAPI;
- веб-интерфейс полного рабочего сценария.

## Запуск

Требуется Python 3.12 или совместимая версия Python 3.

```bash
cp --update=none .env.example .env
make setup
make migrate
make verify
make run
```

После запуска открываем <http://127.0.0.1:8000>. При первом входе интерфейс
предлагает создать единственного оператора. После регистрации выполняется вход,
и становятся доступны бизнес-операции.

Служебные адреса:

- веб-интерфейс: <http://127.0.0.1:8000>;
- Swagger UI: <http://127.0.0.1:8000/docs>;
- OpenAPI: <http://127.0.0.1:8000/openapi.json>;
- health-check: <http://127.0.0.1:8000/health>;
- readiness-check: <http://127.0.0.1:8000/ready>.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `APP_NAME` | `Auction Service` | название в OpenAPI |
| `DATABASE_PATH` | `data/auctions.db` | путь к файлу SQLite |
| `SESSION_TTL_HOURS` | `8` | срок действия сессии в часах |
| `COOKIE_SECURE` | `false` | передача cookie только по HTTPS |

Локальные значения находятся в `.env`. Этот файл не входит в Git.
`.env.example` содержит только безопасный шаблон без секретов.

## Команды

```bash
make setup    # создать .venv и установить зависимости
make migrate  # создать или дополнить схему SQLite
make run      # запустить приложение
make test     # запустить тесты
make quality  # проверить Ruff и форматирование
make verify   # выполнить quality и test
```

Ожидаемый результат `make verify` для версии `v0.1.1`: все проверки Ruff
пройдены, `8 passed`.

## Структура

```text
app/
  auth.py          # хеширование паролей и серверные сессии
  main.py          # маршруты FastAPI, зависимости и обработчики ошибок
  schemas.py       # контракты запросов и ответов
  services.py      # SQL-запросы и бизнес-правила
  db.py            # подключение и инициализация SQLite
  static/          # HTML, CSS и JavaScript веб-интерфейса
schema.sql         # исполняемая реляционная схема
tests/             # автоматические API- и auth-тесты
docs/              # ТЗ, API, модель данных и Git-процесс
```

## Основное бизнес-правило

Продажа возможна только для доступного лота открытого аукциона, активному
покупателю и по цене не ниже стартовой. Вставка продажи и смена статуса лота
на `SOLD` выполняются в одной транзакции `BEGIN IMMEDIATE`. Ограничение
`UNIQUE(sales.lot_id)` дополнительно запрещает повторную продажу. Денежные
значения хранятся целым числом копеек, поэтому ошибки двоичного `float`
исключены.
